# SearXNG との精度比較

RustXNG と上流 SearXNG に同じクエリを投げ、結果がどれだけ一致するかを測りました。

## 方法

- 同じマシンで 2 インスタンスを同時起動（RustXNG :8899 / SearXNG :8001）
- 同じ 8 クエリを、同じエンジン（`engines=` パラメータ）で両方に送信
- 上位 10 件の URL 集合を比較

| 指標 | 意味 |
|---|---|
| `overlap@10` | 上位 10 件の URL 集合の Jaccard 係数（1.00 = 完全一致） |
| `top1` | 1 位の URL が一致した割合 |
| `found` | 何らかの結果が返ったクエリの割合 |

再現:

```bash
python3 bench/compare.py --a http://127.0.0.1:8899 --b http://127.0.0.1:8001 \
  --engines 'pubmed,npm,stack overflow=stackoverflow,arxiv,github,crates.io,docker hub,bing' \
  --queries bench/queries.txt --repeats 1 --delay 0.8
```

## 結果

| エンジン | overlap@10 | top1 | 備考 |
|---|---:|---:|---|
| arxiv | **1.00** | 1.00 | 完全一致 |
| github | **1.00** | 1.00 | 完全一致 |
| crates.io | **1.00** | 1.00 | 完全一致 |
| docker hub | **0.98** | 1.00 | 広告枠 1 件の差 |
| stack overflow | **1.00** | 1.00 | 完全一致 |
| npm | **1.00** | 0.50 | 結果集合は同一、順序が一部異なる |
| pubmed | **1.00** | 0.88 | 結果集合は同一、順序が一部異なる |
| bing | **0.88** | 0.50 | HTML スクレイピングのため広告枠・ページングで変動 |

**主要 8 エンジン中 6 エンジンが完全一致、残り 2 エンジンも 0.88〜0.98** でした。結果集合が同じで順序だけ違うケース（npm / pubmed）は、スコア計算が同じでも元 API の返却順が僅かに違うためです。

## 比較で見つかって直した差分

初回の比較では 3 エンジンで大きな差が出ました。原因を特定して実装を合わせています。

| エンジン | 初回 | 修正後 | 原因 |
|---|---:|---:|---|
| npm | 0.01 | **1.00** | 検索バックエンドが違った（npm registry → 上流と同じ npms.io） |
| stack overflow | 0.00 | **1.00** | ソート順が違った（relevance → 上流と同じ activity）、URL 形式も上流の `/q/{id}` に統一 |
| pubmed | 0.39 | **1.00** | 上流と同じ 2 リクエスト構成（esearch → efetch）に変更 |

pubmed は「1 リクエストしかできない」制約から MEDLINE エクスポートで代替していましたが、オフラインエンジンの実行経路を使えば 2 リクエストできるため、上流と同じ手順に直しました。

## 一致しない・比較できない例

- **duckduckgo / bing の一部**: 短時間に連続で叩くと CAPTCHA や 429 が返り、両方とも 0 件になることがあります（レート制限であり実装差ではありません）
- **wikipedia**: この環境の SearXNG 側が常に 0 件を返すため比較不能
- **HTML スクレイパー系**: 上流とページサイズや広告枠の扱いが同じでも、サイト側の A/B テストで結果が変わることがあります

## 結論

API ベースのエンジンは**上流とほぼ同一の結果**を返します（overlap@10 = 0.98〜1.00）。HTML スクレイパーも、同じパース仕様に合わせれば一致します。差分が出たときは「バックエンド API」「ソート順」「URL 形式」の 3 点を疑うと早く特定できます。
